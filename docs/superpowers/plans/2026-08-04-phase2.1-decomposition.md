### 0.1 — I was wrong about `package_audit` (D2)

It survived 2.0 correctly. `scripts/audit-pbg-repo.py:5` imports
`viva_superpowers.package_audit`. My verification grep scoped to
`viva_superpowers/ skills/ templates/` and **never looked at `scripts/`** — the harness
I then wrote had the same blind spot baked into its `REPOS` loop, because it globbed
`--include='*.py'` over each repo but I validated it only against the module tree.

**Correction folded into the 2.1 harness (§A.0):** the plugin's own repo must be scanned
whole — `viva_superpowers/`, `skills/`, `templates/`, **`scripts/`**, **`server/`**,
**`shim/`**, `docs/`, `pyproject.toml`. Never scope the self-scan to the package
directory. This is now an explicit checklist item, not an implicit property of a glob.

### 0.2 — The endgame contract has to change (correction to my Phase 2.0 review)

I said the endgame was `vivarium_workbench ✗→ viva_superpowers` — drop the dep entirely.
**That is not achievable and should not be the target.** The workbench imports four
modules that D3 pinned as *staying* in the plugin because v2ecoli imports them
workbench-free:

| module | wb stmts | why it must stay in the plugin |
|---|---|---|
| `study_audit` | 3 | `v2ecoli--main/.github/workflows/ci.yml:214` runs it under `--no-install-package vivarium-workbench` |
| `study_evaluator` | 1 | `v2ecoli--main/tests/test_beulig_comparison_harness.py:234` |
| `readout_resolver` | 1 | dep of `study_evaluator` |
| `study_io` | 1 | dep of `study_audit` |

The workbench legitimately needs the study-contract layer (it renders the repro-audit and
the computed-outcomes UI). So the endgame is **not** "no dependency" but **a narrow,
declared, contracted one**:

> **`vivarium_workbench` may import `viva_superpowers` ONLY from the core allowlist:**
> `study_audit`, `study_canonicalize`, `study_io`, `study_evaluator`, `readout_resolver`,
> plus `viz_freshness` and `run_registry` (added in 2.1a, §A.3/§A.4).

That is 26 modules / 63 statements → **7 modules / ~9 statements**, an 86% reduction, and
— more importantly — a *declared* boundary replacing ~50 defensive `try/except
ImportError` guards. Expressed in import-linter as a `forbidden` contract enumerating
everything outside the allowlist (§2.1j).

**Consequence for the stated Phase 2 goal:** the plugin ends as **"skills + a ~4K-LOC
shared study-contract core"**, not "pure agent skills". That was already true after D3;
this makes it explicit and permanent. If that is unacceptable, the only honest fix is the
`viva-core` package I rejected — and the case for it is *weaker* now, not stronger, since
the core has two first-class importers (workbench + v2ecoli) rather than one.

### 0.3 — The drift guards have never run in CI

All 5 mirror tests resolve the canonical via a **sibling checkout**:

```python
CANONICAL = Path(__file__).parent.parent.parent / "pbg-superpowers" / "viva_superpowers" / "<mod>.py"
```
(`tests/test_viz_freshness_mirror.py:11`, `test_runs_index_mirror.py:16`, …)

and `pytest.skip(...)` when it is absent. The workbench's CI workflow does **not** check
out pbg-superpowers. **Every drift guard skips in CI and only ever ran on a developer
laptop that happened to have the sibling.**

This is not theoretical — it has already failed. `vivarium_workbench/lib/refresh_viz.py`
has silently drifted **behind** the canonical and is missing two shipped changes:

```python
# plugin viva_superpowers/refresh_viz.py (canonical, ahead)
run_dir = ep if os.path.isabs(ep) else str(study_dir / ep)
env["VIVA_RUN_DIR"] = run_dir            # ← vendored copy has PBG_RUN_DIR only
```

So the workbench's chart-refresh path does not set the post-rebrand `VIVA_*` env vars and
**does not tag charts with the run that produced them** — which is the input to

`tests/test_runs_index_mirror.py` is worse: its canonical was deleted in 2.0, so it now
skips unconditionally, forever, guarding nothing.

### Modules whose "workbench-only" classification I now doubt

- **`workspace_paths`** (plugin 203 / `lib/workspace_paths.py` 224). The workbench's copy
  is *bigger and independent*; the single plugin import is a drift pin
  (`tests/test_workspace_paths.py:34` is literally `test_drift_guard_against_vivarium_workbench_if_available`).
  It is imported by **31 plugin modules**, several of which stay (the core). **Do not move
  it. Do not dedup it.** Both sides keep their own; sever the one cross-import and delete
  the drift test. Two ~210-LOC path resolvers is the cheap, correct answer here.
- **`composite_spec`** (2 stmts). A real 151-LOC module, *not* a Phase-1 shim, but it is
  the data-first counterpart to process-bigraph's class-based discovery. It probably
  belongs in **process-bigraph**, next to `composite_discovery`/`composite_generator`
  which already moved there in Phase 1. Recommend routing it to process-bigraph in 2.1f
  rather than into the workbench. Also note `lib/notebook_export.py:312,414` emits
  `from viva_superpowers.composite_spec import …` into generated notebooks — that string
  must be repointed with it.
- **`catalog`** (2 stmts). `pyproject.toml:54-57` says the workbench prefers a separate
  ecosystem-ledger dependency and "falls back to pbg-superpowers' stale bundled copy".
  The plugin's `catalog/` may already be dead weight. Verify before moving; likely a
  **delete**, not a move.
- **`event_client`** — I retracted its deletion in 2.0 because
  `vivarium-workbench-main/tests/test_phase_a_e2e.py:5` imports it. That is a *workbench
  test importing the plugin*, i.e. a live test-only reverse edge that 2.1j's contract must
  either allow or resolve. Decide in 2.1j: move `event_client` to the workbench, or scope
  the contract to `vivarium_workbench` (not `tests`).

### Things I would cut or simplify further

1. **`vwb runs backfill` is not needed.** I flagged `backfill_runs` in 2.0 as a deferred
   capability. Re-checked: `vivarium_workbench/lib/backfill_runs.py` has **zero callers**
   anywhere in the workbench — the vendored copy is dead there too. So there is no
   capability to preserve on the workbench side. Delete the vendored copy in 2.1a; the
   plugin keeps the working module and `viva-backfill-runs`. **This deletes the whole of
   my previously-planned 2.1b.**
2. **Do not "merge the feedback trio" as its own step.** Move all three together in 2.1e
   and merge them *inside* the workbench where `lib/study_spec.py:583,595` already calls
   two of them back-to-back. One PR, not two.
3. **Do not move `report` and `report_linter` in the same increment as anything else.**
   `report_linter` is 2,860 LOC with 9 in-package deps and the workbench already has an
   801-LOC `lib/report.py` twin. It gets its own increment (2.1f) and nothing else.
4. **Resist deduping `workspace_paths` / `bibtex` / `imports` / `workspace_yaml` /
   `investigation_status`.** These are name-collisions with independently-evolved
   workbench modules, not vendored mirrors. Deduping them is a semantic merge with no
   drift guard and no external forcing function. Sever the cross-imports; leave both.
